# Games-React

Настольные игры в браузере — «Крестики-нолики», «Шахматы» и «Шашки» — на React и TypeScript. В «Крестиках-ноликах» можно играть вдвоём или против компьютера, в «Шахматах» и «Шашках» — вдвоём на одном устройстве. Локальный профиль хранит статистику побед, поражений и ничьих по каждой игре.

## Features

- **Крестики-нолики** — поля 3×3, 5×5 и 7×7; вдвоём или против компьютера трёх уровней (Easy, Medium, Unbeatable); полное управление с клавиатуры.
- **Шахматы** — все правила ходов, включая рокировку, взятие на проходе и превращение пешки; шах, мат, пат, недостаток материала; часы по 5 минут; список ходов в нотации; отмена хода (Take Back); сдача.
- **Шашки** — обязательное и серийное взятие (серия — один ход), дамка, часы по 5 минут, список ходов, Take Back, сдача.
- **Локальные профили** — регистрация и вход, имя и фото, статистика по каждой игре, сброс статистики отдельной игры, выход без удаления профиля.
- **Мышь и сенсорный экран** — фигуры можно перетаскивать или выбирать касанием (см. [Browser/mobile interaction](#browsermobile-interaction)).

## Tech stack

- **React 18** и **TypeScript** (строгий режим, включая `exactOptionalPropertyTypes`)
- **Vite 6** — dev-сервер и сборка
- **React Router 7** — маршрутизация (hash-адреса вида `/#/chess`)
- **SCSS (Sass)** — стили и анимации; **Lucide React** — иконки
- **Web Crypto** (PBKDF2) — проверка паролей локальных профилей
- **Vitest**, **React Testing Library** и **jsdom** — тесты
- **ESLint 9** и **typescript-eslint** — линтинг
- **npm** — менеджер пакетов (зависимости зафиксированы в `package-lock.json`)

## Getting started

Нужны Git и Node.js 20.19+, 22.13+ или 24+ (вместе с ним ставится npm).

```bash
npm ci
npm run dev
```

Откройте адрес dev-сервера, создайте профиль и играйте.

Приложение нужно открывать на `localhost` или по HTTPS: браузер даёт доступ к Web Crypto (им проверяются пароли) только на защищённых страницах. Если открыть dev-сервер по IP-адресу локальной сети через обычный HTTP, вход и регистрация вежливо откажут с объяснением.

Production-сборка (`npm run build`) кладёт файлы в `dist`; ресурсы подключаются по абсолютным путям, поэтому сборку нужно раздавать из корня домена. `npm run preview` показывает её локально.

npm run typecheck   # TypeScript (приложение, тесты и конфиги); Vite при сборке типы не проверяет

Ещё есть `npm run test:watch` (тесты в режиме наблюдения) и `npm run bench` — замер времени хода компьютера в «Крестиках-ноликах» на фиксированных позициях.

## Architecture

```text
src/
  app/        оболочка: маршруты и вход в профиль (App), провайдеры, навигация
  features/
    games/    шахматы, шашки и крестики-нолики: у каждой игры lib/ (правила), model/ (состояние и действия), ui/ (компоненты);
              games/shared — общий интерфейс партии (часы, ходы, сдача, макет) и общие типы
    profile/  локальные профили: lib/ (хранение, пароли, аватар, статистика), model/ (контекст), ui/ (вход, страница профиля)
  shared/     общие компоненты (Button, IconButton, Modal, FormField, BrandMark), стили и дизайн-токены, помощники для тестов
```

Тесты лежат рядом с кодом (`*.test.ts`, `*.test.tsx`), общая настройка — в `vitest.setup.ts`.

## Game rules / limitations

<details><summary><b>Крестики-нолики</b></summary>

- Поля **3×3**, **5×5** и **7×7**. Первым всегда ходит **X**; ходят по очереди в пустые клетки.
- **3×3:** побеждают 3 знака в ряд; **5×5 и 7×7:** 4 знака в ряд — по горизонтали, вертикали или диагонали. Заполненное поле без линии — ничья.
- **vs Friend** — двое на одном устройстве. **vs Computer** — против компьютера:
  - **Easy** — случайные ходы.
  - **Medium** — выигрывает одним ходом, если может; иначе блокирует такой же ход соперника; иначе ходит случайно.
  - **Unbeatable** — на 3×3 перебирает все варианты (точный минимакс) и не проигрывает. На 5×5 и 7×7 смотрит на 4 хода вперёд, всегда берёт выигрыш в один ход и блокирует такой же ход соперника — это сильнейшая доступная ему игра, но не гарантия непобедимости.
- Настройки: режим, размер поля, а против компьютера — ещё сложность и сторона (X ходит первым, O — вторым). Выбор другого значения начинает новую партию, повторный выбор уже выбранного ничего не меняет.
- Перезапуск обнуляет поле (в том числе пока компьютер думает). С клавиатуры: в порядке Tab одна клетка поля, стрелки двигают фокус, Enter или Пробел ставят знак.

</details>

<details><summary><b>Шахматы</b></summary>

Классические шахматы для двух игроков на одном устройстве.

**Поддерживается:**

- все законные ходы фигур; ход, оставляющий своего короля под шахом, невозможен;
- шах (клетка короля подсвечивается) и мат;
- пат;
- короткая (`0-0`) и длинная (`0-0-0`) рокировка — король и ладья не ходили, между ними пусто, король не под шахом и не проходит через атакованные клетки;
- взятие на проходе;
- превращение пешки в ферзя, ладью, слона или коня на выбор;
- ничья при недостатке материала: король против короля; король и один слон или конь против короля; только короли и слоны, когда все слоны стоят на полях одного цвета (например, король и два однопольных слона против короля);
- часы: по 5 минут, запускаются, когда белые берут первую фигуру; при ≤ 30 с предупреждение, при ≤ 10 с критическое;
- **Take Back** — отменяет последний ход вместе с часами и правами на рокировку; если ход закончил партию, она продолжается (результат остаётся записанным один раз); пока открыт выбор фигуры для превращения, отменяет только выбор;
- **сдача** — после подтверждения (кнопка становится активной через 2 секунды) сдаётся сторона, чей ход, и партия заканчивается победой соперника; новая партия начинается кнопкой **New Game**;
- упрощённая нотация: K, Q, R, B, N (пешка без буквы), `exd8=Q`, без знаков шаха и мата и без уточнения исходной клетки.

**Не поддерживается:** ничья троекратным повторением позиции и по правилу 50 ходов. Реализация не претендует на полное соответствие правилам FIDE.

</details>

<details><summary><b>Шашки</b></summary>

Шашки для двух игроков на одном устройстве — по правилам этого проекта.

- Поле 8×8, фигуры на тёмных клетках; по 12 шашек, белые на рядах 1–3 и ходят первыми.
- Обычная шашка ходит по диагонали на 1 клетку вперёд, а бьёт и вперёд, и назад, перепрыгивая через фигуру соперника.
- **Обязательное взятие:** пока можно бить, ходить могут только бьющие шашки (они отмечены кольцом).
- **Серийное взятие:** если после прыжка та же шашка может бить снова, серия продолжается в том же ходу и записывается одним ходом, например `a3xc5xe7xg5`.
- **Дамка:** шашка, дошедшая до последнего ряда, становится дамкой — и посреди серии тоже, продолжая бить уже как дамка. Дамка ходит по диагонали на любое число клеток, а при взятии встаёт **на клетку сразу за побитой** фигурой.
- **Окончание:** побеждает тот, кто забрал все фигуры соперника или оставил его без хода; проигрывает тот, у кого кончилось время или кто сдался (сдаётся сторона, чей ход).
- Часы по 5 минут, запускаются после первого хода. **Take Back** отменяет последний ход целиком (серию — одним нажатием, вместе с превращением), незаконченную серию — до начала хода.
- **Автоматической ничьей нет.** Это осознанный набор правил проекта, а не реализация определённой федерации.

</details>

## Local profiles

- Профили и статистика хранятся **только на этом устройстве** — в `localStorage` этого браузера. Это локальный профиль, а не онлайн-аккаунт: сервера и синхронизации между устройствами нет.
- Пароль не хранится. Профиль хранит только проверочный хеш **PBKDF2-SHA-256** (Web Crypto, 600 000 итераций, случайная соль для каждого профиля), формат версионирован. Это убирает пароль из хранилища в открытом виде, но не является серверной защитой: всё остальное в профиле видно любому, у кого есть доступ к этому браузеру. Не используйте важные пароли.
- Профили прежних версий, где пароль хранился как есть, переводятся на хеш автоматически при запуске приложения или при входе; вход в систему при этом сохраняется. Если перевод не удался (например, хранилище переполнено), старая запись остаётся и будет переведена при следующем запуске.
- Если браузер не может что-то сохранить (хранилище переполнено или недоступно), приложение говорит «Could not save this profile on this device.» и ничего не теряет: прежние данные остаются как были. Если так не сохранился результат партии, сообщение стоит под результатом, а партия не засчитывается.
- На странице профиля можно сменить имя и фото (фото обрезается до квадрата 200×200), сбросить статистику отдельной игры после подтверждения и выйти. После входа или регистрации открываются «Крестики-нолики».
- **Чей результат записывается:** против компьютера — результат игрока. В партиях вдвоём на одном устройстве статистика считается со стороны **белых** (шахматы, шашки) и **X** (крестики-нолики): победа белых — победа профиля, поражение белых — поражение. Это относится и к сдаче: сдались белые — поражение, сдались чёрные — победа.

## Browser/mobile interaction

- **Перетаскивание** фигуры на подсвеченную клетку — на компьютере.
- **Выбор касанием или кликом** — нажмите свою фигуру (её клетка затеняется и обводится рамкой, возможные ходы подсвечиваются), затем подсвеченную клетку. Повторное нажатие на фигуру снимает выбор, нажатие на другую свою фигуру переключает выбор, нажатие на любую другую клетку снимает его. В шашках во время серии взятий та же шашка остаётся выбранной для следующего прыжка. Работает на сенсорных экранах, где перетаскивание ненадёжно.
- Если перетаскивание закончилось за пределами доски, фигура возвращается, а подсветка снимается.
- **Клавиатура:** все кнопки, диалоги, формы и поле «Крестиков-ноликов» доступны с клавиатуры. Ограничение: фигуры на досках шахмат и шашек клавиатурой не выбираются — для них нужна мышь, касание или перетаскивание.

## Development notes

- Только **npm**: зависимости ставятся через `npm ci` по `package-lock.json` (`npm install` — только при изменении зависимостей). Yarn и pnpm не используются.
- Перед коммитом должен проходить `npm run validate`: без `any`, `@ts-ignore` и отключения правил ESLint.
- Мажорные версии зависимостей обновляются отдельной задачей, а не попутно.
